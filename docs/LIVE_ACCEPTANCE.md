# 真实平台验收

当前状态：已实现初版，真实 BOSS 账号与实时页面尚未验收。离线浏览器测试覆盖的是虚构页面与已确认的协议路径，不宣称等同于实网可用。

1. 在桌面环境运行 `recruit auth login boss`，扫码后检查输出的用户 ID、姓名和 `role`。
2. 运行 `recruit auth status boss`，确认会话可以重新打开并识别同一用户。
3. 求职端搜索一个明确关键词，核对实际职位、城市和招聘者活跃度；招聘端先运行 `positions`，指定一个唯一岗位，核对推荐卡片与候选人活跃度。
4. 先执行 `greet ... --dry-run -n 1`，核对唯一目标及 BOSS 账号当前配置的预制招呼语。
5. 执行该计划，并到 BOSS 沟通记录核对接收人、关联岗位和实际话术。检查本地 `history` 为 `sent`，接口证据指向该目标。
6. 再次执行同一计划，确认没有新增招呼。账号切换、角色变化或页面验证码出现时，确认操作停止并报告真实状态。
7. 用招聘端和求职端分别完成以上流程，记录测试日期、页面版本和结果。不要在文档中保存 Cookie、手机号、候选人简历或其他真实个人信息。

平台 DOM 变化、账号权限、权益不足、验证码或预制话术配置差异可能导致操作不可用。此时应修改 BOSS 适配器并补充对应离线夹具；不在通用服务里添加平台特例，不绕过平台的验证流程。
